### Identify the single interaction that makes or breaks the game


> **Design question:** What single mechanic must feel good for this game to work?
>
> **Time to complete:** 20 minutes
>
> **When to use:** After Worksheets 1 and 2. You need a defined concept and audience before you can correctly identify what the core mechanic needs to deliver.
>
> **What you'll have when you're done:** One named core verb, a defined input→output, a success/failure feel, and a fun hypothesis.

---

## Instructions

A game can have many mechanics. This worksheet is about one: the core. The mechanic the player will perform hundreds or thousands of times. The one that, if it feels bad, makes the whole game fail.

If you list more than one core mechanic, you probably haven't identified the core yet — you've listed features. Keep narrowing until you have one verb.

---

## 1. Core Verb

> What does the player **do** most often in this game? One word. If you need two words, your mechanic might not be atomic enough.
>
> Examples: jump, build, shoot, negotiate, manage, dodge, stack, merge, place, predict

```
The player's core action is: ________________________________
```

---

## 2. Input → Output

> What does the player physically do, and what happens in the game world as a result?
>
> Format: "The player [physical input], and the game [output/response]."

```
The player:

_____________________________________________________________

And the game responds by:

_____________________________________________________________

The time between input and output is approximately: __________
(immediate / 0.5s / 1-2s / longer — faster is usually more satisfying for action mechanics)
```

---

## 3. Success Feel

> When the player executes this mechanic well, what should it feel like? Be specific about sensation, not just "good" or "satisfying."
>
> Examples: "Crisp and snappy, like a click." / "Weighty and impactful, like a physical collision." / "Smooth and flowing, with no resistance."

```
When done well, this mechanic should feel:

_____________________________________________________________

_____________________________________________________________

A real-world analogy for that feeling: _______________________
(e.g., "like catching a ball perfectly," "like solving a puzzle that clicks into place")
```

---

## 4. Failure Feel

> When the player executes this mechanic badly, what should it feel like? Good failure feedback teaches without punishing unfairly.

```
When done badly, this mechanic should feel:

_____________________________________________________________

What should the game communicate when the player fails?

_____________________________________________________________

Is failure immediately readable? (Can the player tell what went wrong?): Y / N
```

---

## 5. Fun Hypothesis

> Complete this sentence without mentioning mechanics. Why is this interaction inherently interesting?

```
"This game is fun because the player gets to ________________

_____________________________________________________________

and that feels good because _________________________________

_____________________________________________________________"
```

---

## 6. Mechanic Dependencies

> What other systems does this core mechanic require in order to function? These are not optional — they're structural dependencies.
>
> Example: If your core mechanic is "place blocks," you need a grid system, a block inventory, and rules for what valid placements mean.

```
For the core mechanic to work, the game also needs:

1. ___________________________________________________________

2. ___________________________________________________________

3. ___________________________________________________________

4. (if applicable) __________________________________________
```

---

## 7. Tuning Levers

> What variables control how this mechanic feels? Naming these now means you know what to adjust during prototype testing.

```
The mechanic's feel is controlled by:

Speed/timing: _______________________________________________
(e.g., how fast the player moves, how quickly the action resolves)

Precision requirement: _______________________________________
(how exact does the player need to be to succeed?)

Feedback intensity: __________________________________________
(how much does the game respond when the player does it right/wrong?)

Consequence weight: __________________________________________
(how much does doing it badly cost the player?)

Other: ______________________________________________________
```

---

## Completion Check

Before moving to Worksheet 4, confirm:

- [ ] I have one core verb (not a phrase, not a list)
- [ ] I can describe the input→output in two sentences
- [ ] I know what success feels like and it's specific (not just "satisfying")
- [ ] I know what the 2–3 structural dependencies are
- [ ] My fun hypothesis doesn't mention mechanics — it describes an experience
