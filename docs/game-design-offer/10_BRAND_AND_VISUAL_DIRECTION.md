# Brand & Visual Direction

> Specialist: UX / IA Lead + Copy and Positioning Lead
> Status: DRAFT — pre-validation

---

## Design Thesis

The landing page should feel like a **well-designed technical document** — not a SaaS dashboard, not a gaming site, not an info-product sales page. The visual language should communicate: precision, methodology, structure, and professional restraint.

The buyer is technical. They respect tools that look engineered, not tools that look marketed.

---

## 1. Palette Direction

### Primary Palette

| Role | Color | Hex (approx.) | Usage |
|------|-------|---------------|-------|
| Background | Near-black | `#0A0A0F` | Page background. Deep, quiet, no blue tint. |
| Primary text | Off-white | `#E8E8ED` | Body text, headlines. Not pure white (reduces glare). |
| Secondary text | Warm gray | `#8A8A96` | Subheadlines, descriptions, secondary info. |
| Accent | Muted amber / warm gold | `#C89B3C` | CTA buttons, highlights, tier badges, key emphasis. |
| Accent secondary | Desaturated blue-gray | `#4A6274` | Borders, subtle highlights, card backgrounds. |
| Card background | Dark gray | `#12121A` | Pricing cards, feature cards, elevated surfaces. |
| Border | Subtle gray | `#1E1E2A` | Card borders, section dividers. Barely visible. |

### Mood Created

Industrial precision. A design workbench, not a party. The amber accent suggests heat and focus — like a cursor on a terminal, like highlighted text in a code editor.

### What to Avoid

| Avoid | Why |
|-------|-----|
| Neon green / cyan / magenta | Gaming aesthetic. Looks like a Twitch overlay or cyberpunk poster. |
| Purple / violet accents | Too close to the reference (DeployVault). Creates derivative impression. |
| Corporate blue | Enterprise SaaS, not indie creator tool. |
| Pure black background (#000) | Too harsh. Looks cheap on OLED screens. |
| Gradient backgrounds | Distracting. Competes with content hierarchy. |
| Multi-color accent scheme | Cluttered. One accent color maximum. |

## 2. Typography Behavior

### Heading Type

**Recommendation:** A geometric sans-serif with strong character. Options:

| Font | Character | Available |
|------|-----------|-----------|
| **Inter** | Clean, neutral, highly readable | Google Fonts (free) |
| **Space Grotesk** | Geometric, technical feel, distinctive | Google Fonts (free) |
| **JetBrains Mono** (headings only) | Monospace, developer-credible | Google Fonts (free) |

**Recommended:** Space Grotesk for headings (technical but warm), Inter for body text (maximum readability).

### Body Type

- Font: Inter or system sans-serif stack
- Size: 16px minimum (18px preferred on desktop)
- Line height: 1.6
- Max width: 680px (prevents long, hard-to-read lines)
- Color: Off-white (#E8E8ED) on dark background

### Hierarchy

| Level | Size (mobile) | Size (desktop) | Weight | Usage |
|-------|--------------|----------------|--------|-------|
| H1 (hero) | 32-36px | 48-56px | Bold (700) | One per page |
| H2 (section) | 24-28px | 32-40px | Bold (700) | Section headlines |
| H3 (subsection) | 18-20px | 24px | Semibold (600) | Card titles, sub-headers |
| Body | 16px | 18px | Regular (400) | Paragraphs |
| Small / Label | 12-13px | 14px | Medium (500), uppercase, letter-spaced | Labels, badges, meta text |

### Monospace Role

Use monospace (JetBrains Mono) sparingly for:
- Labels and category tags ("CORE MECHANIC", "VIABILITY SCORE")
- Small uppercase text elements
- Price display ($19, $39)

Do NOT use monospace for body text or long-form copy. It's hard to read at length.

## 3. Page Mood

### Target Mood

| Keyword | Meaning |
|---------|---------|
| **Precise** | Every element has a clear reason to exist |
| **Engineered** | Feels built, not decorated |
| **Restrained** | Premium through what's absent, not what's added |
| **Document-credible** | Looks like a well-formatted technical spec, not a marketing page |
| **Focused** | One clear path through the page, no distractions |

### What the Page Should NOT Feel Like

| Don't Feel Like | Why |
|----------------|-----|
| A SaaS product page | No app screenshots, no feature grids, no "trusted by X companies" |
| A gaming website | No neon, no pixel art, no controller icons, no "epic" language |
| An info-product sales page | No urgency timers, no testimonial carousels, no "limited time" |
| A portfolio site | No hero images, no showreel, no gallery |
| A Notion template marketplace listing | No casual handwriting fonts, no pastel colors, no emoji-heavy headers |

## 4. Card / Table Logic

### Pricing Cards

- Dark card background (#12121A) on darker page background (#0A0A0F)
- Subtle border (1px, #1E1E2A)
- Tier 2 card: accent border (1px, amber) + "Most Complete" badge
- Internal spacing: generous (24px+ padding)
- Feature list: checkmark icon in accent color + text
- CTA button: full-width within card

### Feature/Artifact Cards

- Minimal cards — just a subtle background elevation
- Number or icon + name + one-line description
- No heavy borders or shadows
- Consistent spacing between cards

### Tables (if used in FAQ or comparison)

- No heavy grid lines
- Alternating row backgrounds with very subtle difference
- Header row in slightly lighter background
- Left-aligned text, right-aligned numbers

## 5. Accent Usage

### Where Accent (Amber) Should Appear

| Element | Usage |
|---------|-------|
| CTA buttons | Primary action buttons — solid amber background, dark text |
| Tier 2 card border | Highlight the recommended tier |
| "Most Complete" badge | Small label on Tier 2 card |
| Checkmarks in feature lists | Small icon color |
| Hover states on interactive elements | Subtle amber glow or underline |
| Price numbers ($19, $39) | Accent color to draw the eye |

### Where Accent Should NOT Appear

| Element | Why |
|---------|-----|
| Body text | Hard to read on dark background |
| Backgrounds (large areas) | Overwhelming, loses premium feel |
| Multiple accent colors | Cluttered, unfocused |
| Decorative elements (lines, shapes) | No decoration for decoration's sake |
| Section dividers | Keep these invisible or very subtle |

### Maximum Accent Percentage

**Target:** Accent color should occupy less than 5% of any given screen. It's a signal, not a theme.

## 6. Visual Proof Surfaces

### What Should Exist on the Page

| Visual Type | Purpose | Priority |
|-------------|---------|----------|
| Worksheet preview (1-2 images) | Make the product tangible. Show what the buyer gets. | HIGH |
| Viability Scorecard preview | The most impressive artifact — show its structure | HIGH |
| Step/process diagram (text-based) | Show the 5-phase methodology | MEDIUM |
| Pricing cards with feature lists | Visual comparison of tiers | HIGH |
| Founder photo (small, optional) | Humanize the seller | LOW |

### What Should NOT Be Used

| Avoid | Why |
|-------|-----|
| Stock photos | Instant credibility loss with technical audience |
| Generic illustrations (isometric, flat art) | SaaS cliché. Not game-design credible. |
| 3D renders or mockups | Too polished for a worksheet product. Creates expectation mismatch. |
| Screenshots of other games | Copyright issues. Distracting from the product. |
| Decorative background patterns | Cluttered. Competes with content. |
| Video embeds (v1) | Too expensive to produce. Delays launch. |

### Making a Digital Download Feel Tangible

The biggest visual challenge: the product is PDFs and markdown files. It must LOOK like it has substance.

**Tactics:**
1. Show a styled preview of the Viability Scorecard (formatted, with example scores)
2. Show a partial view of the Core Loop Mapper (with the structure visible)
3. Use a "product stack" visual — a subtle representation of the artifact count (e.g., a list with document icons)
4. Use content density as proof — the pricing card feature list, if long enough, signals depth

## 7. What to Avoid

### Visual Anti-Patterns

| Pattern | Why It Fails for This Product |
|---------|------------------------------|
| Countdown timers | Fake urgency. Game devs see through it. |
| "Only X left" badges | Digital product. There is no scarcity. |
| Testimonial carousels with stock photos | Obviously fake. Instant trust destruction. |
| Gradient mesh backgrounds | Trendy but distracting. No information value. |
| Parallax scrolling effects | Gimmicky. Slows mobile performance. |
| Floating chat widgets | No support infrastructure to back it up. |
| Cookie consent banners (oversized) | Blocks the hero. Use a minimal toast if legally required. |
| Auto-playing video | Annoying. Burns mobile data. |
| Multi-step checkout (in-page) | Use Stripe's hosted checkout. It's simpler and more trusted. |

## 8. Inspiration Direction

### Directionally Correct Aesthetics

Think about the visual language of:
- **Technical documentation sites** (Stripe Docs, Tailwind CSS) — clean hierarchy, generous whitespace, content-first
- **Design system sites** (Radix, Shadcn) — restrained, component-focused, dark mode done well
- **Developer tool marketing** (Linear, Raycast) — premium through simplicity, not through decoration
- **Research paper layouts** — structured, hierarchical, table-driven, proof-oriented

### Game-Design-Specific Visual Language

| Element | How to Use |
|---------|-----------|
| Flowchart aesthetics | The "How It Works" section could use a simple flowchart-style layout |
| System diagram feel | The artifact list could be presented as interconnected nodes |
| Wireframe line quality | Thin, precise lines for borders and dividers |
| Grid/table structure | Feature lists and comparisons in clean table format |
| Blueprint-like precision | Consistent spacing, alignment, mathematical proportions |

### What NOT to Reference

| Don't Look Like | Why |
|----------------|-----|
| DeployVault specifically | Too derivative. Different product, different audience. |
| Gumroad product listings | Associated with low-effort info products |
| Udemy/Coursera | Course marketplace aesthetic. Wrong product type. |
| Steam store pages | Wrong context entirely |
| Dribbble portfolio shots | Designed to impress designers, not convert buyers |

---

## Summary: Visual Direction in One Sentence

**A dark, restrained, document-driven landing page that feels like a well-engineered technical tool — not a marketing page, not a gaming site, not an info-product pitch.**
